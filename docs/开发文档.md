安兔兔数据源迁移工程计划书

1. 项目背景

当前 App 内的安兔兔排行榜数据通过客户端实时爬取安兔兔官网 HTML 页面获得，该方案存在以下问题：

· 每次打开页面都需要实时请求并解析，首屏加载速度受网络波动影响较大
· 安兔兔页面结构调整时需要发版更新 App 端的解析逻辑
· 用户设备网络环境差异导致部分用户加载失败

为解决上述问题，计划将数据采集与数据消费分离：通过云端定时任务预先爬取并结构化存储，App 端仅负责数据拉取与展示。

2. 总体目标

· 将安兔兔数据采集逻辑从 App 端剥离，迁移至云端定时任务
· App 端保留现有解析逻辑作为降级兜底，确保服务可用性
· 新旧方案共存，通过配置开关控制数据源切换，降低上线风险

3. 方案概述

3.1 云端侧

在现有 json 仓库中配置 GitHub Actions 定时任务：

· 触发规则：每日定时执行（建议凌晨低峰期）
· 任务内容：爬取安兔兔各榜单页面，解析后合并为单一 JSON 文件
· 产出物：backend/antutu/antutu_rank.json
· 分发方式：复用现有的 3 条 CDN 线路（Gitee / 自建 / jsDelivr）

3.2 App 端

· 核心逻辑：新增 AntutuFetcher，优先请求云端 JSON 数据，请求失败时自动降级到本地 AntutuParser（现有 Jsoup 解析逻辑）
· 现有逻辑：AntutuParser、Jsoup 依赖、UI 页面均保留不动
· 数据模型：保留现有 AntutuRankItem 等数据类，反序列化 JSON 时复用
· UI 层：仅需调整数据来源调用，页面结构保持不变

6. 技术要点

· AntutuFetcher 的 JSON 拉取需复用现有 NetworkClient 及 3 条线路容灾机制
· JSON 反序列化使用 kotlinx.serialization，与项目现有方案一致
· 降级逻辑应具备熔断/超时控制，避免因等待 JSON 超时导致页面长时间加载
· 云端脚本需考虑 User-Agent 伪装、请求间隔等反爬策略

7. 验收标准

· App 端正常展示安兔兔各榜单数据，页面无报错
· 云端 JSON 文件可正常访问，数据结构完整
· JSON 数据可用时，页面加载速度显著优于原实时爬取方案
· JSON 数据不可用时，App 自动降级到本地解析，数据仍可正常展示

8. 风险与应对

风险 应对
