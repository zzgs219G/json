

GitHub Trending 采集模块 · Agent 执行计划

任务：为 json 仓库新增 GitHub Trending 数据采集能力，按语言 × 时间维度抓取热门仓库元数据。

---

1. 任务目标

在 backend/github_trending/ 目录下生成结构化 JSON 数据，使 App 端能够展示"今日/本周/本月"热门项目，并支持按语言筛选。

---

2. 数据源

· URL 模式：https://github.com/trending/{language}?since={since}
· language：语言名称，空字符串表示"全部"
· since：daily | weekly | monthly

---

3. 必须采集的字段（每个仓库）

字段 说明
nameWithOwner 格式 owner/repo
repoUrl GitHub 仓库地址
description 项目描述
language 编程语言
stargazerCount 总 Star 数
forkCount Fork 数
todayStars 当前周期内新增 Star 数

---

4. 语言列表

抓取以下语言（含"全部"）：

```
全部, Python, JavaScript, TypeScript, Go, Rust, Java, C++, C#, PHP, Swift, Kotlin, Dart, Ruby, Shell
```

Agent 可根据实际运行情况调整此列表（例如移除响应异常的冷门语言）。

---

5. 输出目录结构

按时间维度合并（每维度一个文件，语言在文件内按 reposByLanguage 分组，避免碎片化小文件）：

```
backend/github_trending/
├── daily.json                     # 今日：全部语言
├── weekly.json                    # 本周：全部语言
└── monthly.json                   # 本月：全部语言
```

---

6. 维度文件结构（daily.json / weekly.json / monthly.json）

· dimension：{ since: 维度值, label: 显示标签（今日/本周/本月）}
· updatedAt：生成时间（ISO 格式，含时区）
· languages：该文件内实际包含的语言名称列表
· reposByLanguage：语言显示名 → 仓库对象数组 的映射（"全部"键包含所有语言）

---

8. 技术要求

· 使用 requests + BeautifulSoup 解析 HTML（与现有 antutu_crawler.py 风格一致）
· 请求间隔 ≥ 1.5 秒，避免触发限流
· 超时设置 20 秒，单次失败不影响整体任务
· User-Agent 使用主流浏览器标识

---

9. 新增文件清单

文件 职责
scripts/github_trending.py 爬虫主脚本
.github/workflows/github-trending.yml 定时任务（每日 UTC 20:00）

---

10. 验收标准

☐ 3 个维度 JSON 文件（daily/weekly/monthly.json）全部生成，每文件含 15 种语言
☐ 维度文件结构与 App 端约定一致（dimension / updatedAt / languages / reposByLanguage）
☐ 每个 reposByLanguage 语言数组长度 > 0（单个语言×维度至少 10 条）
☐ 单次运行时间 < 120 秒
☐ Workflow 推送时 commit message 带 [skip ci]

---

11. 约束与边界

· 不抓取 Release、README、Commit 历史等任何需要 GitHub API 的数据
· 不保留 历史版本，每日全量覆盖
· 允许 部分语言/维度失败（降级处理，不影响整体任务状态）

---

12. 执行顺序

1. 新增 scripts/github_trending.py
2. 本地验证（python scripts/github_trending.py --out backend）
3. 新增 .github/workflows/github-trending.yml
4. 提交并观察首次 CI 运行结果

---

如果 Agent 在实现过程中遇到 GitHub 页面结构变化导致解析失败，或某个特定语言持续返回空数据，可自行决定跳过该语言并在日志中记录。
